**Feature Branch**: `001-fullstack-todo-app`

**Created**: 2026-05-22

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 회원가입 및 로그인 (Priority: P1)

처음 방문한 사용자가 이메일과 비밀번호로 계정을 만들고 로그인하여 자신만의 할 일 공간에 접근한다.

**Why this priority**: 인증 없이는 사용자별 데이터 분리가 불가능하므로 모든 기능의 전제 조건이다.

**Independent Test**: 회원가입 후 로그인 → 메인 화면 진입까지 독립적으로 검증 가능하며, 이 단계만으로도 "내 공간" 접근이라는 가치를 전달한다.

**Acceptance Scenarios**:

1. **Given** 미가입 사용자가 로그인 화면을 열었을 때, **When** 이메일과 비밀번호를 입력하고 회원가입을 누르면, **Then** 계정이 생성되고 메인 화면으로 이동한다.
2. **Given** 이미 가입한 사용자가 로그인 화면을 열었을 때, **When** 올바른 이메일·비밀번호를 입력하면, **Then** 메인 화면으로 이동하고 자신의 할 일 목록만 표시된다.
3. **Given** 로그인된 사용자가 로그아웃을 누르면, **Then** 로그인 화면으로 돌아가고 다른 사용자의 데이터는 접근 불가하다.
4. **Given** 잘못된 비밀번호를 입력하면, **Then** "이메일 또는 비밀번호가 올바르지 않습니다" 오류 메시지가 표시된다.

### User Story 2 — 할 일 CRUD (Priority: P1)

로그인한 사용자가 할 일을 생성·조회·수정·삭제하고 완료 처리할 수 있다.

**Why this priority**: 앱의 핵심 기능으로, 이것 없이는 다른 어떤 뷰도 의미가 없다.

**Independent Test**: 할 일 추가 → 목록 확인 → 완료 체크 → 삭제까지 전체 흐름이 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 메인 화면에서, **When** 새 할 일 추가 버튼을 누르고 제목·카테고리·우선순위·마감일을 입력하면, **Then** 목록에 즉시 나타나고 저장된다.
2. **Given** 할 일 목록에서, **When** 체크박스를 클릭하면, **Then** 해당 할 일이 완료 상태로 변경되고 완료 섹션으로 이동한다.
3. **Given** 할 일 상세 패널에서, **When** 제목·메모·서브태스크·마감일을 수정하면, **Then** 변경 사항이 즉시 저장되고 목록에 반영된다.
4. **Given** 할 일을 삭제하면, **Then** 목록에서 즉시 사라지고 복구할 수 없다.
5. **Given** 서브태스크가 있는 할 일에서, **When** 서브태스크를 완료 처리하면, **Then** 서브태스크 완료 개수/전체 개수가 업데이트된다.
6. **Given** 별표(즐겨찾기)를 클릭하면, **Then** 별표 상태가 토글되고 별표 필터에서 확인 가능하다.

---

### User Story 3 — 카테고리 필터링 (Priority: P2)

사용자가 카테고리별로 할 일을 필터링하고 각 카테고리의 할 일 개수를 실시간으로 확인한다.

**Why this priority**: 많은 할 일을 효율적으로 탐색하는 핵심 UX 기능이다.

**Independent Test**: 특정 카테고리 클릭 → 해당 카테고리 할 일만 표시 확인으로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사이드바에서 카테고리를 클릭하면, **Then** 해당 카테고리의 할 일만 목록에 표시된다.
2. **Given** 할 일을 추가·완료·삭제하면, **Then** 사이드바의 카테고리별 개수가 즉시 업데이트된다.
3. **Given** "전체" 카테고리를 선택하면, **Then** 모든 할 일이 표시된다.

---

### User Story 4 — 캘린더 뷰 (Priority: P2)

사용자가 월간 캘린더에서 마감일 기준으로 할 일을 시각적으로 확인하고 날짜별 할 일 목록을 조회한다.

**Why this priority**: 일정 관리 맥락에서 할 일을 파악하는 중요한 보조 뷰다.

**Independent Test**: 캘린더 탭 이동 → 마감일 있는 할 일 확인 → 날짜 클릭 → 해당 날 할 일 목록 표시로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 캘린더 화면에서, **When** 마감일이 설정된 할 일이 있으면, **Then** 해당 날짜 셀에 이벤트가 표시된다.
2. **Given** 날짜 셀을 클릭하면, **Then** 그 날 마감인 할 일 목록이 표시된다.
3. **Given** 이전/다음 월 이동 버튼을 누르면, **Then** 해당 월의 캘린더와 이벤트가 표시된다.

---

### User Story 5 — 통계 뷰 (Priority: P3)

사용자가 자신의 할 일 완료 패턴을 시각적으로 파악하고 생산성 인사이트를 얻는다.

**Why this priority**: 사용자 동기 부여에 기여하지만 핵심 CRUD 기능 이후에 구현 가능하다.

**Independent Test**: 통계 탭 이동 → 완료율 KPI·카테고리 비율·주간 현황·히트맵이 실데이터 기반으로 표시 확인.

**Acceptance Scenarios**:

1. **Given** 통계 화면에서, **When** 할 일 완료·추가가 있으면, **Then** 완료율 KPI가 실시간 데이터로 표시된다.
2. **Given** 통계 화면에서, **Then** 카테고리별 비율 차트, 주간 완료 막대 그래프, 연속 달성 히트맵이 모두 표시된다.

---

### User Story 6 — 모바일 뷰 (Priority: P3)

모바일 기기 사용자가 단일 컬럼 레이아웃과 하단 탭바로 앱을 편리하게 사용하고 FAB로 빠르게 할 일을 추가한다.

**Why this priority**: 모바일 접근성은 중요하지만 코어 기능 완성 후 적용 가능하다.

**Independent Test**: 모바일 해상도에서 탭바 전환·FAB 동작·할 일 추가 흐름 전체 검증.

**Acceptance Scenarios**:

1. **Given** 모바일 화면에서, **When** 하단 탭바의 탭을 누르면, **Then** 해당 화면(메인/캘린더/통계)으로 전환된다.
2. **Given** 모바일 화면에서, **When** FAB(+) 버튼을 누르면, **Then** 새 할 일 추가 폼이 열린다.

---

### Edge Cases

- 비밀번호 재설정이 필요한 경우 어떻게 처리하는가? → v1 범위 외, 추후 구현
- 오프라인 상태에서 할 일을 수정하면? → 마지막으로 불러온 데이터를 유지하고 "오프라인" 안내를 표시한다
- 동일 이메일로 중복 가입 시도 시? → "이미 가입된 이메일입니다" 오류 표시
- 마감일 없이 할 일을 생성하면? → 캘린더에 표시되지 않고 목록에서는 정상 표시
- 서브태스크가 있는 할 일을 삭제하면? → 서브태스크도 함께 삭제된다
- 반복 설정된 할 일을 완료하면? → 다음 반복 일정이 자동 생성된다 (v1에서는 단순 완료 처리)

## Requirements *(mandatory)*

### Functional Requirements

**인증**
- **FR-001**: 시스템은 이메일·비밀번호로 신규 계정 생성을 허용해야 한다.
- **FR-002**: 시스템은 이메일·비밀번호로 기존 계정 로그인을 허용해야 한다.
- **FR-003**: 로그인한 사용자는 자신의 데이터만 조회·수정·삭제할 수 있어야 한다.
- **FR-004**: 사용자는 로그아웃할 수 있어야 하며, 로그아웃 후 인증된 페이지 접근이 차단되어야 한다.
- **FR-005**: 유효하지 않은 인증 정보 입력 시 구체적인 한국어 오류 메시지를 표시해야 한다.

**할 일 CRUD**
- **FR-006**: 사용자는 제목, 카테고리, 우선순위, 마감일, 메모를 포함한 새 할 일을 생성할 수 있어야 한다.
- **FR-007**: 시스템은 할 일에 서브태스크(최대 10개)를 추가·수정·삭제·완료 처리할 수 있어야 한다.
- **FR-008**: 사용자는 할 일의 모든 필드를 수정할 수 있어야 한다.
- **FR-009**: 사용자는 할 일을 삭제할 수 있어야 한다.
- **FR-010**: 사용자는 할 일을 완료/미완료로 토글할 수 있어야 한다.
- **FR-011**: 사용자는 할 일에 별표(즐겨찾기)를 설정·해제할 수 있어야 한다.
- **FR-012**: 시스템은 모든 변경 사항을 클라우드에 즉시 저장해야 한다.

**카테고리 필터**
- **FR-013**: 사용자는 카테고리(업무/개인/학습/건강/쇼핑/전체/별표)로 할 일을 필터링할 수 있어야 한다.
- **FR-014**: 시스템은 카테고리별 미완료 할 일 개수를 실시간으로 표시해야 한다.

**캘린더 뷰**
- **FR-015**: 시스템은 마감일이 설정된 할 일을 월간 캘린더의 해당 날짜에 표시해야 한다.
- **FR-016**: 날짜 셀 클릭 시 해당 날 마감인 할 일 목록을 표시해야 한다.
- **FR-017**: 사용자는 이전·다음 월로 이동할 수 있어야 한다.

**통계 뷰**
- **FR-018**: 시스템은 전체 완료율 KPI를 실데이터로 표시해야 한다.
- **FR-019**: 시스템은 카테고리별 할 일 비율 차트를 실데이터로 표시해야 한다.
- **FR-020**: 시스템은 최근 7일간 일별 완료 막대 그래프를 표시해야 한다.
- **FR-021**: 시스템은 최근 12주간 달성 히트맵을 표시해야 한다.

**모바일 뷰**
- **FR-022**: 모바일 해상도에서 하단 탭바(메인/캘린더/통계)로 화면을 전환할 수 있어야 한다.
- **FR-023**: 모바일에서 FAB 버튼으로 새 할 일 추가 폼을 열 수 있어야 한다.

**오프라인 / 동기화**
- **FR-024**: 네트워크 연결이 없을 때 마지막으로 불러온 데이터를 유지하고 오프라인 상태를 사용자에게 안내해야 한다.
- **FR-025**: 연결 복구 시 데이터를 자동으로 새로고침해야 한다.

### Key Entities

- **User**: 이메일, 비밀번호(해시), 생성일시
- **Todo**: 제목, 카테고리, 우선순위, 마감일, 메모, 완료 여부, 별표 여부, 반복 설정, 생성일시, 수정일시, 소유 사용자
- **Subtask**: 제목, 완료 여부, 순서, 소속 Todo
- **Category**: ID(업무/개인/학습/건강/쇼핑), 이름, 색상 (시스템 고정값)

## Success Criteria *(mandatory)*

- **SC-001**: 사용자가 회원가입부터 첫 할 일 추가까지 2분 이내에 완료할 수 있다.
- **SC-002**: 할 일 추가·수정·완료 처리가 1초 이내에 화면에 반영된다.
- **SC-003**: 로그인한 사용자가 다른 사용자의 할 일에 접근할 수 없다 (데이터 격리 100%).
- **SC-004**: 오프라인 전환 시 기존에 불러온 데이터가 유지되고 오프라인 안내가 5초 이내에 표시된다.
- **SC-005**: 캘린더·통계·모바일 뷰 모두 실데이터로 동작하며 목 데이터가 표시되지 않는다.
- **SC-006**: 모바일 기기(화면 너비 390px 기준)에서 모든 핵심 기능(할 일 추가·완료·삭제)을 사용할 수 있다.

## Assumptions

- 소셜 로그인(네이버, 카카오)은 v1 범위 외다. UI에 버튼이 있더라도 기능 구현은 추후 진행한다.
- 비밀번호 재설정 기능은 v1 범위 외다.
- 반복 설정은 저장만 하고 자동 생성 로직은 v1 범위 외다.
- 동시 접속 중인 다른 기기와의 실시간 동기화(Realtime)는 v1 범위 외이며, 페이지 로드 시 최신 데이터를 불러오는 방식으로 구현한다.
- 카테고리는 5가지로 고정이며 사용자가 직접 추가·수정할 수 없다.
- 기존 목 데이터(`components/data.jsx`)는 실제 데이터로 교체되며, 인증되지 않은 상태에서는 표시되지 않는다.
- 다크모드/라이트모드·테마 설정은 유지하되 클라우드 동기화 대상이 아니다 (로컬 설정).
